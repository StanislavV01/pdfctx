# pdfctx v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship pdfctx v0.1: PDF → section tree + blocks with page/bbox → SQLite index → seven agent tools over stdio MCP, streamable-HTTP MCP and FastAPI, with an audit log.

**Architecture:** A `Library` façade over a SQLite store is the only thing the interfaces call. Parsing (pdfplumber + pypdf) produces blocks; the outline builder attaches them to sections; FTS5 provides BM25, an optional embedder adds vectors and RRF fuses both. MCP (mcp 2.x `MCPServer`), FastAPI and the CLI are thin adapters.

**Tech Stack:** Python ≥ 3.11, pdfplumber, pypdf, sqlite3/FTS5, mcp 2.3, FastAPI, uvicorn; pytest, reportlab, ruff, httpx (dev); fastembed (optional).

**Spec:** `docs/superpowers/specs/2026-11-27-pdfctx-design.md`

## Global Constraints

- Package `pdfctx`, `src/` layout, hatchling build, console script `pdfctx = pdfctx.cli:main`.
- Runtime deps exactly: `pdfplumber>=0.11`, `pypdf>=5`, `mcp>=2.3,<3`, `fastapi>=0.115`, `uvicorn>=0.30`. Extra `embed = ["fastembed>=0.4"]`. Dev: `pytest`, `reportlab`, `ruff`, `httpx`.
- IDs: document `id` = first 12 hex chars of sha256(absolute path); section `{doc_id}:s{n}`; block `{doc_id}:b{n}`; table blocks are blocks with `kind="table"`.
- `bbox` = `(x0, top, x1, bottom)` in PDF points, top-left origin, rounded to 1 decimal.
- Token estimate = `ceil(len(text) / 4)` everywhere.
- Document `status` ∈ `ok | no_text | encrypted | failed`; non-`ok` documents are listed with their status and never crash indexing of other files.
- FTS5 tokenizer `unicode61 remove_diacritics 2`; user text never reaches FTS5 syntax unescaped.
- Upload limits: 20 MB, 300 pages, body must start with `%PDF-`.
- Tool errors are `PdfctxError` with a one-line message; interfaces show the message, never a traceback.
- Commits: Conventional Commits, author `Stanislav <83041246+StanislavV01@users.noreply.github.com>`, no trailers. FastAPI is not installable in the build sandbox: API tests use `pytest.importorskip("fastapi")` locally and run for real in CI.

## Review Focus

1. Queries with FTS5 metacharacters (`"`, `-`, `AND`, `NEAR(`, `*`, `:`, unbalanced parens, empty or punctuation-only): must return results or an empty list, never an SQL error — Task 6 test `test_search_survives_fts_syntax`.
2. Encrypted, corrupt, empty (0 pages) and image-only PDFs in a folder: other files still index; statuses `encrypted`/`failed`/`no_text` are reported — Task 5 test `test_index_folder_with_bad_files`.
3. A file edited or deleted after indexing: next call re-indexes or drops it, and stale block ids return "unknown block" instead of old text — Task 5 test `test_reindex_on_change_and_delete`.
4. Polish/Ukrainian text: `zażółć` matches `zazolc` and Cyrillic words are searchable — Task 6 test `test_search_diacritics_and_cyrillic`.
5. Two-column pages: paragraphs from the left column come before the right column and are not interleaved line by line — Task 3 test `test_two_column_reading_order`.

### Task 4: Outline builder

**Files:** Create `src/pdfctx/outline.py`; Test `tests/test_outline.py`.

**Interfaces:**
- Consumes: `ParsedDoc`.
- Produces: `@dataclass Section(idx: int, parent: int | None, level: int, title: str, page: int)` and `build_outline(doc: ParsedDoc) -> tuple[list[Section], list[int | None]]` — the second list gives the section `idx` for each block (same order as `doc.blocks`). With bookmarks: sections from bookmarks; each block belongs to the last bookmark whose page ≤ block page and, on the same page, whose title matches a heading block at or above it (normalized: casefold, whitespace collapsed). Without bookmarks: heading blocks become sections; level from numbering depth (`2.1` → 2) when present, else rank of distinct heading sizes (largest = 1). A virtual root is not stored; blocks before the first section get `None`.

### Task 6: Search (BM25, optional vectors, RRF)

**Files:** Create `src/pdfctx/search.py`, `src/pdfctx/embed.py`; Test `tests/test_search.py`.

**Interfaces:**
- Produces in `embed.py`: `class Embedder(Protocol): dim: int; def embed(self, texts: list[str]) -> list[list[float]]`; `FastEmbedder(model="BAAI/bge-small-en-v1.5")` importing fastembed lazily (clear `PdfctxError` if the extra is missing); `HashEmbedder(dim=256)` — deterministic hashed bag-of-words, used by tests and as a no-download fallback; `get_embedder(name: str | None) -> Embedder | None` for `None | "hash" | "fastembed"`.

### Task 7: Context: read_section, cite, context_pack

**Files:** Create `src/pdfctx/context.py`; Test `tests/test_context.py`.

**Interfaces:**
- Produces: `tokens(text) -> int`; `render_section(store, section_id, max_tokens) -> dict` → `{"section": {...}, "path": [titles root→leaf], "blocks": [block dicts], "truncated": bool, "next_block_id": str | None}` — includes sub-sections in order, stops before exceeding the budget; `cite(store, block_id) -> dict` → `{"block_id","document","file","page","bbox","section_path","text"}`; `context_pack(store, hits: list[Hit], budget_tokens: int) -> dict` → `{"sections": [{"path": [...], "blocks": [{"block_id","page","text","kind"}]}], "used_tokens", "budget_tokens", "dropped": int}` — for each hit in score order add the block plus its immediate previous paragraph when it is in the same section and the hit is shorter than 40 tokens; skip ids already added; stop when the next block would exceed the budget; finally sort blocks by `(doc, order)` and group by section path. Block dict shape is shared by all three: `{"block_id","kind","page","bbox","text"}` plus `"rows"` for tables.
